# Rivu 路线图与进度

这是项目进度的唯一入口：现在能用什么、离发布还差什么、以后做什么。产品的取舍原则见 [`product/constraints.md`](product/constraints.md)，实现细节以 [`architecture/system-design.md`](architecture/system-design.md) 为准。

最近更新：2026-11-19。

## 一句话

功能主体已经做完并且验证过。离第一个公开版本 v0.1.0 还差 3 件事，都列在下面的「v0.1.0 还差什么」里。

## 目标

Rivu 是开源、自托管、完全免费的网站访问统计，用来替代 Plausible。服务对象是个人和小团队。三个重点按顺序是：**快、好用、接入轻**。

v0.1.0 的部署形态只有一种：一个 `rivu` 程序，加 PostgreSQL 和 ClickHouse 两个数据库，前面放 nginx 或 Caddy。不做集群。

## v0.1.0 还差什么

状态只用四个词：**未开始**、**待确认**（东西做出来了，等你看过点头）、**进行中**、**完成**。

| # | 事项 | 为什么要在发布前做 | 状态 | 做完的标准 |
|---|---|---|---|---|
| 1 | 周报邮件排版 | 现在只发纯文本，所有站点、所有期的标题都一样，邮箱里会叠成一串 | 待确认：[`designs/weekly-report/email.html`](../designs/weekly-report/email.html) | 周报和确认邮件都有排版好的版本和纯文本版本；标题带站点名和日期 |
| 2 | 安装更省事 | 现在要先克隆代码、在本机编译镜像，再手写一段脚本生成 9 个密钥 | 未开始 | 不用编译：直接拉取发布好的镜像；密钥一条命令生成；从空机器到看到第一条访问不超过 10 分钟 |
| 3 | 发布演练 | 发布流程写好了但从没真正跑过；而且它只认正式版本号，没法先试一次 | 未开始 | 加一个不影响正式版本的预发布通道，用它发一次，再用发出来的镜像在空机器上装通 |

第 1 项需要你先确认原型，才能动邮件代码。第 2、3 项互相关联：发布演练跑通之后才有可拉取的镜像。

## 已经能用的

每一行都已经实现，并且有测试或验收记录。

### 装起来

| 能做什么 | 说明 |
|---|---|
| 一个镜像跑全部功能 | 一个 161 MB 的镜像，包含服务端、看板和采集脚本 |
| 一条命令启动 | `docker compose` 启动 rivu 和两个数据库；可以用自带的 Caddy 自动申请证书，也可以接已有的 nginx |
| 升级与回退 | 启动时自动升级数据库结构；失败不会启动新版本 |
| 备份与恢复 | 两个脚本；演练过「删掉全部数据再恢复」，数据一致 |

### 把网站接进来

| 能做什么 | 说明 |
|---|---|
| 一行代码接入 | 采集脚本压缩后约 870 字节；带外链、下载、表单统计的完整版约 2.6 KB |
| 不用 Cookie | 不读写 Cookie，不写浏览器存储，访客不需要点同意 |
| 单页应用 | 自动识别前端路由的页面切换 |
| 安装验证 | 装完脚本后，看板会告诉你有没有收到第一条访问 |
| 接入诊断 | 数据不对时，能看到收到了多少、丢掉了多少、每种原因丢了多少 |
| 过滤 | 自动识别机器人和垃圾来源；可以按 IP、国家、页面、域名屏蔽 |

### 看数据

| 能做什么 | 说明 |
|---|---|
| 看板 | 访客、访问、浏览量、跳出率、访问时长；趋势图；来源、页面、国家和地区、设备 |
| 指标说明 | 图表上方用一句话说明当前指标怎么算，例如访客是「同一个人一天内来多次只算一次」 |
| 筛选与对比 | 按来源、页面、国家、设备等筛选；与上一周期对比；实时在线人数 |
| 目标 | 把某个页面或某个事件设成目标，看多少人完成了 |
| 自定义属性 | 给事件带上自己的属性（例如文章分类），在看板里按属性查看和筛选 |
| 给别人看 | 公开看板；带密码和有效期的共享链接 |
| 拿走数据 | 导出当前视图为 CSV；查询 API；命令行查询 |

### 管理

| 能做什么 | 说明 |
|---|---|
| 多人协作 | 邀请成员，四种角色；也可以只邀请某个人看某一个站点 |
| 账号安全 | 两步验证和恢复码；查看和退出登录设备 |
| 数据保留 | 原始数据保留多久可以设置；过期后汇总数据仍然保留，长期趋势还能看 |
| 删除数据 | 删除某段日期的统计，或者删除整个站点（7 天内可恢复） |

### 从 Plausible 搬过来

| 能做什么 | 说明 |
|---|---|
| 导入历史数据 | 上传 Plausible 的数据导出文件，或者用命令行导入；用一份真实导出核对过，数字一致 |

### 邮件（可选，配置了发信服务才有）

| 能做什么 | 说明 |
|---|---|
| 邀请和找回密码 | 没配置发信服务时，邀请改为复制链接 |
| 周报 | 每周一封，上一整周的访客、访问和浏览量。在账号页订阅：点邮件里的链接确认一次邮箱，之后每个能看的站点一个开关；周报里的退订链接只关掉那一个站点 |

### 快与稳

| 指标 | 实测 |
|---|---|
| 查询速度 | 3000 万行数据、查 30 天：不走缓存 150 毫秒内，走缓存 5 毫秒内（95% 的请求） |
| 数据多久可见 | 访问发生后约 1 秒 |
| 数据库重启 | 重启 ClickHouse 100 次，一条数据都没丢 |
| 程序崩溃 | 强杀 rivu 100 次，每次最多丢最后 1 秒的数据，没有重复 |

## v0.1.0 之后

下面这些不进 v0.1.0。按「对个人和小团队有多大用」排了先后。

| 功能 | 它是什么 | 决定 |
|---|---|---|
| 阅读进度目标 | 统计有多少访客把页面读到了某个位置，比如读到 75%。写文章的人可以用它看文章有没有被读完。采集脚本已经在记录滚动位置，只差把它设成目标。原型里已经画了 | v0.2 候选，排第一 |
| 保存筛选条件 | 把一组常用的筛选条件起个名字存起来，下次一键套用，比如「来自搜索引擎的手机访客」。现在筛选条件都在网址里，收藏网址能达到同样效果 | v0.2 候选，排第二 |
| 目标的附加条件 | 目标只在事件带着某个属性值时才算数，比如只统计「套餐 = 专业版」的注册。原型里已经画了 | 有人需要再做 |
| 漏斗 | 看访客在一连串步骤里走到哪一步离开。例如 100 人打开定价页，30 人点了注册，12 人注册成功，就知道最大的流失在第一步。适合有注册或下单流程的产品团队 | 暂不做，理由见 [`product/constraints.md`](product/constraints.md) |

## 已知限制

- 每个进行中的访问占用约 685 字节内存，比最初估计的大，有已知的优化办法（`system-design.md` §4.6）。
- 长时间范围的查询用的是按天汇总的数据，有三处已知的近似：跨午夜的访问在两天里各算一次；只按部分维度分组时访客数可能偏多；某天汇总完成后才到的数据不会补进去（`system-design.md` §6.4）。

## 验收记录

早期文档用 P0 到 P4 称呼各个阶段，研究报告里还在引用这些名字，这里保留对照和当时的验收标准。

| 阶段 | 内容 | 状态 |
|---|---|---|
| P0 基础 | 工程骨架、单个程序、配置、数据库迁移、CI | 完成 |
| P1 最小闭环 | 采集脚本、接入、访问归并、查询、公开 API、看板。任务与验收见 [`brief-p1.md`](brief-p1.md) | 已通过验收 |
| 交付 | 镜像、生产部署文件、反向代理示例、安装与升级文档、发布流程 | 完成，尚未发布 |
| P2 性能 | 按天汇总、自动选择数据层、结果缓存、数据保留期、压测 | 完成 |
| P3 可靠 | 崩溃与重启测试、备份恢复演练、告警建议 | 完成 |
| P4 产品 | 属性报表、导入、导出、邮件、两步验证、周报 | 完成；漏斗等移出范围，见上 |

**P2 的验收**：3000 万行规模上常见报表 95% 的请求在 300 毫秒内返回，访问发生到可见 95% 在 5 秒内。实测见 [`research/load-test-2026-10.md`](research/load-test-2026-10.md)。

- 按天汇总：10 组维度，按站点当地的日期构建，可重复执行；改时区会重建；删除统计数据时一并删除（`system-design.md` §5.5）。
- 自动选层：已汇总的日期走汇总数据，其余走原始数据，两者在一条查询里合并；对照测试 `rollup_tier.rs` 验证两边结果一致（§6.4）。
- 结果缓存：按时间范围分桶，删除数据后按站点失效（§6.9）。
- 每个组织的查询并发和超时有上限。
- ClickHouse 的数据分片、合并、变更有监控指标，越线告警。
- 原始数据保留期：实例上限 `RIVU_RETENTION_DAYS`，站点可以调短；保留期之前的日期由汇总数据回答。

**P3 的验收**：持续写入时强杀 rivu、重启 ClickHouse 各 100 次。ClickHouse 重启不丢数据；rivu 崩溃丢失的数据不超过崩溃前还没写入的那一批；没有重复数据。实测见 [`research/fault-injection-2026-10.md`](research/fault-injection-2026-10.md)。

- 故障注入：`tools/faults/run.sh`。
- 备份与恢复：`deploy/backup.sh`、`deploy/restore.sh`；演练 `tools/backup-drill/run.sh`，小数据量恢复用时 11 秒。
- 告警建议：`platform-and-ops.md` §10。

## 怎么更新这份文档

- 一件事只在一个表里出现一次。做完了就从「还差什么」挪到「已经能用的」。
- 状态只用上面那四个词。写「待确认」时，写清楚要确认的东西在哪。
- 第一次出现的专有名词，用一句话加一个例子解释它。
- 改了范围（加进或移出某个版本），同时改 [`product/constraints.md`](product/constraints.md) 里的取舍表。
