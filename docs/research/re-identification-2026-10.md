# 重识别测试（2026-10，开发库）

日期：2026-10-27。验收项：`docs/brief-p1.md`「用数据库导出做重识别测试，结论写进隐私说明」。
工具：`tools/reident`（只读：ClickHouse 用 reader 账号，PG 只读 `salts` 的日期，不读盐的值）。
原始输出：`docs/research/re-identification-2026-10/`（`all.json` 全部数据，`loadgen.json` 只含 loadgen 生成的站点）。
结论已写进 [`docs/privacy.md`](../privacy.md)。

**数据是合成的**：开发库里约 75 万个事件，99.5% 来自 `tools/loadgen`（UA 取自 uap-core 测试集的 10,114 个浏览器 UA，每个会话一个随机公网 IP），其余来自端到端测试。下面的「机制」结论（能不能关联、能不能还原）与数据来源无关；「比例」结论（多少访客可被唯一确定）只说明方法，真实站点要用真实导出重跑（见「复跑」）。

## 攻击者模型

攻击者拿到了数据库导出：ClickHouse 的 `events` / `sessions`，可能还有 PostgreSQL 的导出。他想做两件事之一：

- 把某个已知的人（知道他的 IP、浏览器、城市，或者他访问过某个页面）对应到数据里的事件；
- 把数据里的访客跨天串起来，形成浏览历史。

## 结果

| 检查 | 结果 | 判断 |
|---|---|---|
| 1. 同一个 `visitor_id` 的事件跨度超过 48 小时 | 0（123,517 个站点内访客 ID） | 访客 ID 只在一个站点本地日内有效，不能跨天关联 |
| 2. `session_id` 跨过 24 小时的会话 | 0；最长 1.7 小时 | 设计允许连续活跃的会话最长 7 天，这时 `session_id` 会把它跨过的几天串起来（见下文「已知的关联」）；合成数据里没有这样的会话 |
| 3. 一天内由（国家、地区、城市、设备、浏览器与版本、系统与版本）唯一确定的访客 | 28.2%（loadgen 站点）、28.6%（全部） | 合成 UA 的多样性远高于真实流量，比例偏高；但机制成立：小站点上，罕见的浏览器版本加城市可能对应到一个人 |
| 4. URL 与属性里的个人信息（邮箱、9 位以上数字、IPv4） | 邮箱 0、IPv4 0；9 位以上数字 322 行，都是 loadgen 探针路径里的时间戳 | URL 规范化只保留 pathname 与白名单参数，查询串里的邮箱、令牌不会进库；pathname 本身里的个人信息（`/users/alice`）由站点决定，Rivu 不改写 |
| 5. 盐的寿命 | PG 里有 2026-10-24 … 2026-11-08 的盐 | 10-24 … 10-27 是 `salts_rotate` 应保留的（UTC 今天 10-26 的 −2 … +1）；10-28 以后的来自写未来日期数据的测试，生产里不会出现 |
| 5. 有盐时还原 IP 的成本 | SipHash-2-4 单核约 19 M 次/秒：遍历全部 IPv4 × 1 个 UA 约 4 分钟；× 1000 个常见 UA 约 62 小时（单核，可线性并行） | **盐存在期间（最多约 2 天），同时拿到盐与事件的人可以还原 IPv4**，见下文 |

## 关键发现：盐与事件同时泄露时，IPv4 可以被还原

`visitor_id = SipHash-2-4(salt, site_id ‖ ip ‖ ua)`。盐只有 16 字节，但它存在 PG 里；IPv4 只有 2³² 个，UA 的取值也集中在少数常见浏览器上。所以：

- 拿到某天的盐、事件表和一个人的 UA（或者一组常见 UA），遍历全部 IPv4 就能找到哪个 IP 产生了某个 `visitor_id`。单核 4 分钟一个 UA，一台 16 核机器几十秒。
- 反过来更便宜：已知某人的 IP 与 UA，算一次哈希就能确认他那天有没有访问过、访问了什么（确认攻击）。
- 盐删除之后（`salts_rotate` 删除早于 UTC 今天 −2 的盐），只剩 128 位随机盐上的哈希，无法遍历，这些 `visitor_id` 就不能再关联到任何 IP。
- 不只 Rivu 如此：任何「日盐 + IP + UA」的访客哈希（Plausible 同样）都有这个窗口。区别在于盐放在哪里、留多久。

现有的缓解（设计里已有）：
- 盐只在 PG，不进 ClickHouse、日志与错误上报；
- PG 备份排除 `salts` 表的数据（`platform-and-ops.md` §11：`--exclude-table-data=salts`）；
- 盐两天后删除。

建议：给访客哈希的 key 再混入一个不在数据库里的服务端密钥，这样只拿到数据库导出（哪怕含盐）也不能遍历；代价是密钥丢失或更换时，当天的访客 ID 会断开一次。已采纳：collector 必填 `RIVU_VISITOR_PEPPER`（或 `_FILE`），key = `SHA-256("rivu-visitor-key-v1" ‖ 长度 ‖ 密钥 ‖ 盐)` 的前 16 字节（`docs/privacy.md`）。

## 已知的关联（设计如此）

- **会话内**：同一会话的事件共享 `session_id`。连续活跃（间隔不超过 30 分钟）的会话最长 7 天，跨过的几个本地日因此被串起来；超过 30 分钟不活跃或满 7 天就是新会话，之后无法关联。
- **一天内**：同一站点同一本地日，同一 IP 加同一 UA 的访问共享 `visitor_id`。
- **准标识符**：会话属性（地理、设备、浏览器与系统的主次版本）与时间戳本身就有区分度。地理精度可以按站点设为国家、地区或城市（`site_settings.geo_level`）；浏览器与系统只存主次版本。

## 复跑

```bash
# 对任意实例（只读）：ClickHouse reader 账号；PG 连接串可省（省略则不检查盐的日期）
REIDENT_CH_PASSWORD=… REIDENT_DATABASE_URL=postgres://… \
  cargo run --release -p reident -- --ch-url http://… --sites <站点 id> --out result.json
```

`--ua-candidates` 调整暴力成本估算里的 UA 个数；`--sites` 省略则检查全部站点。真实站点的第 3 项（唯一访客比例）才有意义，建议在隐私说明里按真实数据更新。
