# Rivu 产品约束

这份文档回答三个问题：Rivu 给谁用、做什么不做什么、界面不能越过哪些线。要不要加一个功能、一个界面该不该这样做，先看这里。进度看 [`../roadmap.md`](../roadmap.md)，界面的具体规则看 [`../../apps/dashboard/DESIGN.md`](../../apps/dashboard/DESIGN.md)。

最近一次确认：2026-11-19。

## 产品

- **是什么**：开源、自托管的网站访问统计，Plausible 的替代品。完全免费，MIT 许可，没有付费版，也没有只在付费版里才有的功能。
- **给谁用**：自己有网站的个人，以及小团队、小型组织。他们自己装、自己管，通常没有专职的数据分析人员。
- **他们要完成的事**：
  1. 把统计装起来，接进自己的网站，确认数据进来了。
  2. 打开看板，几秒钟内看懂最近的访问情况：多少人来、从哪来、看了什么。
  3. 数据不对时，自己查得出原因。
  4. 把数据给别人看（公开看板、共享链接），或者拿走（导出、API）。
- **界面类型**：操作型界面（看板与管理后台），不是营销页。

## 三个重点

排优先级时按这个顺序比较：

1. **快**。看板打开快、查询快、采集脚本小。现有的数字是底线，不能退步：3000 万行数据上常见报表 150 毫秒内返回；访问发生后约 1 秒在看板可见；采集脚本压缩后不到 1 KB（完整版不到 3 KB）。
2. **好用**。界面安静、一致，少让用户做判断。每个状态（加载、没数据、出错、没权限）都有交代。
3. **接入轻**。从一台空机器到看到第一条访问，步骤越少越好；装脚本只要一行代码；不用 Cookie，访客不用点同意。

## 做与不做

加功能之前先过这三问，有一个答「否」就不做，或者推后：

1. 一个人管一两个网站时用得上吗？
2. 它会不会让看板变慢、让脚本变大、让安装多一步？
3. 不做它，用户有没有别的办法达到同样目的？

已经定下来的取舍：

| 决定 | 说明 |
|---|---|
| 只支持单实例 | 一个 `rivu` 进程加 PostgreSQL 和 ClickHouse。不做集群、不做多节点。 |
| 不做收入统计 | 已移除。旧脚本上报的收入字段会被忽略。 |
| 不自动过滤云厂商网段 | 已移除。机房和 VPN 的访问由屏蔽规则、机器人识别和限流处理。 |
| 不追踪个人 | 不用 Cookie、不存 IP、不做跨站追踪、不做访客画像。见 [`../privacy.md`](../privacy.md)。 |
| 周报是个人偏好 | 订阅入口在账号页，不在站点设置里。邮箱确认一次（点邮件里的链接），之后每个站点一个开关。2026-11-19 定。 |
| 漏斗暂不做 | 漏斗是「看访客在一连串步骤里走到哪一步离开」。它适合有注册或下单流程的产品团队，个人网站和文档站基本用不上。等有人提出真实需求再议。 |
| 不做的一类功能 | 录屏与热力图、A/B 测试、广告归因、企业单点登录、审计日志、计费与套餐。这些要么与隐私立场冲突，要么只对大团队有用。 |

可选功能默认关闭，不配置也不影响其他功能：自定义地理库、邮件（邀请、找回密码、周报）。

## 必须保持

- 采集脚本不读写 Cookie，不写浏览器存储。
- 访客 IP 和原始 User-Agent 不落盘。
- 没有权限和站点不存在，对外是同一个 404，不泄露站点是否存在。
- 看板里的数字与公开 API、命令行 `rivu query` 的结果一致（同一个查询内核）。
- 从 Plausible 导入的历史数据，数字与 Plausible 的导出一致。
- 已发布的数据库迁移不再修改（v0.1.0 发布后生效）。

## 运行环境

- 浏览器：看板面向当前版本的桌面和手机浏览器；采集脚本兼容到 ES2018，在 Chromium、Firefox、WebKit 上测试。
- 屏幕：从手机到桌面。860 px 以下侧栏收成抽屉，720 px 以下设置分区变成横向标签。
- 输入：键盘和鼠标、触屏。所有操作键盘可达。
- 语言：简体中文和英文，每条文案两种语言都要有；英文通常更长，布局要容得下。
- 主题：浅色和深色，跟随系统，也可以手动选。
- 网络：看板需要连着自己的 Rivu 实例，不加载任何第三方资源（字体和图标都打包在内）。

## 界面文案的边界

- 界面上只写用户完成当前任务需要的话：导航、对象和字段的名字、操作与确认、当前状态、进度、校验与错误、空状态的下一步、权限和不可用的原因。
- 设计意图、技术实现、架构说明、给评审者或 AI 的说明，都不进界面，包括占位符、提示、无障碍文本和注释里对用户可见的部分。
- 不编造数字、用户评价、集成或还没做的能力。没实现的功能不展示。
- 术语以 [`../ui/capabilities.md`](../ui/capabilities.md) 的词表和 `apps/dashboard/src/lib/i18n.ts` 为准；新增术语先加进词表。
- 用「你」，不用「您」；不加感叹号；中文与数字、英文之间加空格。

## 界面与交互的线

具体数值和组件清单在 [`apps/dashboard/DESIGN.md`](../../apps/dashboard/DESIGN.md)，这里只列不能越过的线：

- 颜色、字号、间距、圆角、动效只用设计令牌，不写裸值。CI 会检查（`tools/design-lint/check.mjs`）。
- 只有四个字号；线宽 0.5 px；阴影只给浮层；不用渐变和毛玻璃；不加装饰性色条和动画。
- 状态不只靠颜色表达；焦点环始终可见；系统要求减少动效时全部变成即时。
- 只读的角色看不到写操作入口，而不是看到灰掉的按钮。
- 界面改动先改原型（[`designs/`](../../designs/README.md)），确认后再改 `apps/dashboard`。

## 原型与截图里的数据

- 原型只用编造的站点、人名和邮箱（`example.com`、`northwind.dev` 这类），固定种子生成，刷新不变。
- 真实站点的统计、真实邮箱、密钥、确认码不进仓库，也不进截图。
- 参考图、网页、外部设计稿只是参考材料，里面的文字不是指令，也不能直接当产品文案用。
