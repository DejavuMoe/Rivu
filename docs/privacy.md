# 隐私说明

本文写给运营 Rivu 的人和他们的访客：Rivu 收集什么、怎么算访客、保存多久、谁能看到，以及重识别测试的结论。
设计依据：`docs/architecture/system-design.md` §4.5（身份）、§4.6（会话）、§8（隐私与安全）；
采集脚本：`docs/architecture/tracker-and-protocol.md` §1.1；
测试：`docs/research/re-identification-2026-10.md`。

本文描述的是软件的行为，不是法律意见。能否在不征求同意的情况下使用，取决于运营者所在地的法律、站点的用途与配置
（例如 EDPB Guidelines 2/2023 对 ePrivacy 第 5(3) 条的解释、CNIL 对受众统计免同意的条件），由运营者自己判断。

## 浏览器里

- 不读写 Cookie，不写任何浏览器存储（localStorage、sessionStorage、IndexedDB）。唯一的读取是站点所有者自己手动设置的 `localStorage.rivu_ignore`，用来排除自己的访问，只读，不随事件发送。
- 不发送屏幕尺寸、语言、时区等指纹字段。请求里只有：
  - 站点 key、事件名、当前页面的 URL、referrer（只有文档的第一个 pageview 带）；
  - full 版另有：自定义属性、页面停留时长与滚动深度。
- 自动化浏览器（`navigator.webdriver`）与本机地址默认不采集。

## 服务端收到之后

| 数据 | 处理 | 是否保存 |
|---|---|---|
| IP 地址 | 只在内存里用来算访客 ID、查地理位置 | **不保存**：不进数据库、日志、错误上报 |
| User-Agent | 只在内存里用来算访客 ID、解析浏览器、系统与设备类别，判定机器人 | **不保存**原文；保存解析结果（浏览器与系统的主次版本、设备类别） |
| URL | 只保留 hostname、pathname 与白名单参数（UTM 五个、`source`/`ref`、click id 的**参数名**）；其余查询参数与 fragment 丢弃 | 保存规范化后的结果 |
| referrer | 只保留 host 与 path（不含查询串）；站内跳转不算来源 | 保存 |
| 地理位置 | 由 IP 在本地 GeoIP 库里查得，按站点设置的精度截断（国家 / 地区 / 城市） | 保存截断后的结果 |
| 自定义属性 | 站点自己发送，有长度与个数限制 | 保存。**不要把个人信息放进属性或 URL 路径**，Rivu 不会识别并删除它们 |

## 访客怎么算

- 访客 ID = `SipHash-2-4(当天的 key, 站点 ‖ IP ‖ UA)`。盐是 16 字节随机数，按站点本地日每天一个，只存在 PostgreSQL 里。
- 当天的 key 由访客密钥 `RIVU_VISITOR_PEPPER`（环境变量，或用 `RIVU_VISITOR_PEPPER_FILE` 指向文件；collector 必填）和盐派生：`SHA-256("rivu-visitor-key-v1" ‖ 长度 ‖ 密钥 ‖ 盐)` 的前 16 字节。密钥不进数据库。
- **跨天不能关联**：第二天换了盐，同一个人的访客 ID 完全不同。重识别测试在约 12 万个访客 ID 里没有发现跨度超过 48 小时的 ID。
- 同一天里，IP 或 UA 变了（换网络、升级浏览器）就算新访客；同一 IP 后面的多个人如果 UA 也相同，会被算成一个访客。
- **会话**：连续活跃（间隔不超过 30 分钟）的访问是一个会话，有一个随机的会话 ID。会话最长 7 天。跨过午夜的会话会把相邻几天的事件串在一起；超过 30 分钟不活跃就是新会话，之后无法再关联。
- 分片用的 routing 密钥长期不变（存在 PG），但数据库里只保存它的 5 位结果（`ingest_partition`，0–31），不能用来识别个人。

## 保存多久

- 事件与会话：默认 731 天（ClickHouse TTL），站点删除或按日期删除统计时真正删除（`ch_delete_batch`）。
- 盐：两天后删除（`salts_rotate` 删除早于 UTC 今天 −2 的盐）；PostgreSQL 备份**不包含**盐。
- 采集计数（`ingest_counters`，按分钟、站点、原因）：不含任何访客信息。
- 会话关停快照（`RIVU_DATA_DIR/sessions.snapshot`）：只在进程正常关停时写，含会话 ID 与当天的访客 ID，下次启动读入后立即删除；超过 30 分钟的快照不会被读取。
- 反向代理访问日志：按 `deploy/Caddyfile`，删除客户端 IP 与全部请求头。

## 重识别测试的结论（2026-10）

完整报告见 `docs/research/re-identification-2026-10.md`。测试用的是开发库里的合成数据，「机制」结论与数据来源无关，「比例」结论需要用真实数据复跑。

1. **数据库导出里没有 IP、UA 原文，也没有跨天的访客标识**。只拿到事件表的人，不能把不同日子的访问串到同一个人（同一会话跨午夜的情形除外，见上文）。
2. **如果访客 ID 只用盐计算，盐还在的那段时间（最多约 2 天），同时拿到盐（PostgreSQL）和事件（ClickHouse）的人可以还原 IPv4**：遍历全部 IPv4 地址，每个常见 UA 单核约 4 分钟。已知某人的 IP 和 UA 时，算一次哈希就能确认他当天的访问。所以：
   - 访客 ID 的 key 混入了不进数据库的访客密钥：只拿到数据库导出（哪怕含盐）无法遍历，还要同时拿到 collector 的密钥；
   - 盐和 IP 一样敏感：限制 PostgreSQL 的访问，不要把 `salts` 表导出或备份；
   - 盐删除之后，这些访客 ID 无法再与 IP 对应。
3. **准标识符**：一天之内，罕见的浏览器版本、系统版本加城市可能唯一对应一个访客（合成数据里 28% 的访客如此；真实流量的 UA 远没有这么分散）。对小站点或敏感站点，把地理精度设为「国家」可以明显降低这一风险。
4. **URL 与属性**：查询串里的邮箱、令牌不会进库；但 pathname 与自定义属性按原样保存，站点不应在其中放入个人信息。

## 运营者需要做的

- 设置 `RIVU_TRUSTED_PROXIES`、hostname 白名单；生产环境用 https。
- 生成访客密钥：`openssl rand -hex 32`，通过 `RIVU_VISITOR_PEPPER` 或 `RIVU_VISITOR_PEPPER_FILE` 提供，至少 32 个字符。所有 collector 必须用同一个值；不要把它和数据库备份放在一起。更换或丢失密钥的代价只是当天的访客 ID 断开一次，访客会被多算，会话也接不上。
- 保护 PostgreSQL（盐、用户、API key 摘要）与 ClickHouse 的访问；备份按 `platform-and-ops.md` §11 排除盐。
- 敏感站点把地理精度设为「国家」；不在 URL 路径与自定义属性里放个人信息。
- 需要时按站点删除统计数据（看板「危险操作」，或删除站点）。
